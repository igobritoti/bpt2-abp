## Bounded BPT2 fixture

Matching rule under test:

`exact Unicode City label + exact uppercase two-letter StateCode`

No accent folding, case folding, synonym table, fuzzy match, geocoder, centroid fallback, or inferred rename is applied.

Ten fixed cases were executed:

- `6` exact matches;
- `4` fail-closed unmatched presentation/conflict/unknown cases;
- `0` ambiguous matches.

Controls include Alta Floresta D'Oeste/RO, Porto Alegre/RS, São Paulo/SP, Salvador/BA, Brasília/DF and Fernando de Noronha/PE. Deliberate negatives include `Sao Paulo`, lowercase `porto alegre`, a conflicting UF and an unknown city.

This is a bounded fixture, not production Listing coverage. The repository's current location values are generated by test/smoke flows rather than a retained production corpus.

## Decision

`MUNICIPALITY_IDENTITY_AUTHORITY = IBGE_DTB_2025_PINNED`

`EXACT_CITY_UF_PROJECTION = PROVED_BOUNDED`

`CITY_ALONE_AS_STABLE_IDENTITY = REJECTED`

`SPECIAL_CITY_LEVEL_UNITS = PRESERVE_EXPLICITLY`

`HEURISTIC_LOCATION_NORMALIZATION = NOT_AUTHORIZED`

`TRUE_LISTING_RADIUS = STILL_BLOCKED_ON_LOCATION_POINT_AUTHORITY_AND_PRIVACY`

`CENTROID_RADIUS = NOT_PROVED`

`POSTGIS = NOT_SELECTED`

## Consequence

BPT2 now has evidence for an official municipality/city-level identity authority and a fail-closed exact matching baseline. This does not authorize persistence changes, a public radius filter, vehicle coordinates, municipality centroids as vehicle locations, travel distance, geocoding, or PostGIS adoption.

A later implementation slice may project an IBGE code only after its storage/update/rename semantics are explicitly bounded. True physical radius remains a separate product/privacy/location-authority problem under #116.
